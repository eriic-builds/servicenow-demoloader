Prerequisites & installation

Set up Scout's ServiceNow account

Use your Human admin to create demo.seeder, then install SN DemoLoader and test read access in Scout.

Use your own practice PDI. Never production.

These are powerful permissions, not a production or least-privilege setup.

No account is created by this guide or installer. Do steps 1-7 first.

4. Set its own password

In the saved demo.seeder User record

Done when: The Machine password is saved privately.

  1. On the saved user, click Set Password.
  2. Set a strong, unique password. Do not reuse your admin or Microsoft password.
  3. Save it in your password manager. You need this same password in the config later.
  4. Keep Password needs reset and Locked out off. Click Update if changed.
Why Machine + Web service access only?

Scout uses this account for headless API calls. A person cannot log in as demo.seeder through the interactive UI. That is intentional. Keep your Human admin for browser work. Later, use Scout's Test read access, not website sign-in.

Never put the password in chat, this guide or config JSON.

8. Install, then connect in Scout

Back on your Windows computer

Done when: Scout's Test read access succeeds.

Install the local skill

  1. Get the SN-DemoLoader-Scout ZIP from a publisher you trust.
  2. Right-click the ZIP: Extract All... > Extract.
  3. Open the extracted version folder. Double-click Install.cmd, not config HTML. Do not run as administrator.
  4. When prepared, type READY. Read the trust prompt; type TRUST only if approved. Enter cancels. GUIDE reopens these steps.
  5. Wait for ok: true. Then restart Scout.

READY is your acknowledgement, not a connection test. Installation creates no source users or roles.

Tell Scout what to use

  1. In chat: /sn-demoloader > Configure or select environment.
  2. In Environment, enter a config name, your PDI base URL and demo tenant.
  3. Choose Use existing account and Existing Machine account (recommended).
  4. Machine user ID: demo.seeder. Admin user ID: your separate Human admin.
  5. Confirm authorization only for your own practice environments. Click Save config, then Use this config.
  6. Open Access. In Machine account password, enter the password you saved in step 4.
  7. Click that card's Save password, then Test read access. Stop if it fails.
  8. Add intended People. Return to chat; review exact changes before approving source work.

For the HR pack, choose Load HR knowledge pack in chat. It needs one existing configured Knowledge author/manager. Connector setup is separate.

Stuck? Open only what you need

Stop here if you are stuck
Users link, field, role or Edit is missing

Sign in as Human admin. Fallback: All > User Administration > Users. If sign-in returns home, click the Users link again. Release layouts vary; ask your PDI administrator. Do not invent fields/roles or change ACLs.

401, 403, interactiveRequired or a sign-in page

Check: PDI awake, correct URL/login/password, Active, Machine, Web service access only, roles, no lockout/reset. These errors do not establish the cause. Stop rather than bypass authentication, MFA or add more roles.

Blocked installer, update or recovery

Use the trusted ZIP's Install.cmd. Signed-only devices need IT-approved delivery; never bypass policy. Restart Scout if the skill is missing. For interrupted installs, use Install.cmd Diagnose and see the recovery instructions. Never delete PDI locks/journals.

Old login or private data

An existing demo_seeder login is different: do not rename or duplicate it blindly. Never upload passwords, configs or run history to GitHub.

Sandbox recipe, not least privilege. Admin may include other roles. Guide checks are self-reported, not source/access/connector verification.

No passwords are collected, no background requests are made, and your checklist and PDI address are not saved.
